## 2026-08-30 · BC-003 修复：47 条 interactions 接入检索 · tag: bc003-interactions

- 改了什么：`_all_items()` 把**顶层** `kg["interactions"]` 纳入检索范围；`_node_text` 识别 event/trigger/resolution 字段
- 为什么：`_node_lists()` 只遍历 `nodes.Cyber_Minghan` 下三层，而 interactions 在 KG **顶层**，47 条事件性记忆（trigger→resolution）一条都召回不到
- 依据：实验 EXP-004——8 个 interactions 独有片段（nodes 中完全不存在的文本）召回数 **0 → 8**
- 流程：这是第一次完整走「预登记 → 修复 → 回归测试 → 结题」闭环。
  假设在**动手前**修正过一次（原称基线为 0，实测共有词仍能从 nodes 召回 5 条，
  故指标改为只看 interactions 独有片段），修正已留痕在 `hypothesis_revised` 字段
- 回归测试：3 条（顶层 interactions 可检索 / resolution 字段参与匹配 / 原三层不退化）。
  **已做注入故障验证**：把改动回退后测试立刻失败，确认守得住
- 效果：badcase 回放覆盖率 67% → **78%**（BC-003 从 MANUAL 变为真被守住）
- 回滚：`git revert` 本 commit；检索范围恢复三层
