## 1. 定位

**可信的个人代理——深度在记忆治理，不在工具数量。**

三个"不做"构成差异化：不做微信个人号自动回复（合规）｜不冒充本人欺骗面试官（诚信）｜不堆通用工具生态（不跟 Hermes 比数量）。

## 3. 重排后的优先级（三条主线）

### 主线 A：对外（主页 Agent）—— 服务求职，最高优先级

| 序 | 事项 | 说明 |
|---|---|---|
| A1 | 可见性硬隔离 | **真实漏洞**：`retrieve` 不过滤 visibility，对外暴露会泄露 private 节点 |
| A2 | 只答检索到的 + 引用校验 | 回答强制带 `[uuid:xxxx]`，代码校验引用是否来自本次检索结果 |
| A3 | 话题敏感度三态 | public / guarded / private，按「后果主导、语档次之」选策略 |
| A4 | 移动端主页 | 身份声明 + 引导问题 + 引用溯源 + 转真人口 |

### 主线 B：对内（个人助理）

| 序 | 事项 | 说明 |
|---|---|---|
| B1 | 邮件只读 + 草拟 | Gmail API + OAuth，**绝不自动发送**，HITL 天然契合 |
| B2 | 校验 Agent / 记忆管理员 Agent | 压幻觉 + 权限隔离（对话 Agent 只给读权限） |

### 主线 C：记忆内核（可信度）

| 序 | 事项 | 说明 |
|---|---|---|
| C1 | 判别测试骨架（persona fidelity） | **唯一不被环境阻塞的量化项**；30 题 + 5 位评判者盲评 |
| C2 | 打分量纲归一化 | 让 `vector_alpha` 真正成为权重 |
| C3 | `load_memory` 检索词问题 | 整句中文做关键词匹配命中率≈0 |
| C4 | interactions 接入检索 | 47 条带 trigger→resolution 的数据目前运行时取不到 |
| C5 | 真实跑分 + 接入 nightly CI | 需要联网环境 |

## 4. 降级与砍掉（含理由）

| 项 | 原计划 | 新判定 | 理由 |
|---|---|---|---|
| KG 迁 SQLite | 阶段 3 | **降级** | 全库仅 16.2k tokens，JSON 完全够用；迁移是"看起来专业"而非"解决问题" |
| 结构化日志 | 阶段 3 | **降级** | 单机自用场景，日志价值有限；等有多个用户/需要排查线上问题时再做 |
| 全图检索 | — | **等数据** | 全库边数=0、规模未到；Zep 的增益集中在时序/多跳，需先用分题型召回率证明需求 |
| 微信 | — | **不做** | 合规信息矛盾，待查官方文档；企业微信客服是可考虑的合规通道 |
| MCP | — | **暂缓** | 现在做是"我们调别人工具"无差异化；将来做是"别人用我们记忆"才是壁垒 |
| 统一错误处理 | 阶段 3 | **并入 A1** | 对外模式的错误语义与内部不同，一起做避免返工 |
