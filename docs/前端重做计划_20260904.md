# 前端重做计划（2026-09-04，Mac 优先）

## 0. 为什么重做

现有前端是**像素世界**（Phaser 游戏引擎），跟"帮你处理正事的个人助理"这个定位拧：

- 形态不符：玩游戏的方式不适合干活
- 版权存疑：星露谷风格素材（待决策 A4 一直挂着）
- 缺关键能力：没有记忆面板，看不到回答依据什么——**而这正是我们跟聊天机器人的唯一区别**

## 1. 设计原则（决定所有取舍）

| 原则 | 说明 |
|---|---|
| **记忆可见、可干预** | 不是黑盒。用了哪条记忆、能不能改、是不是过时了，都要看得见 |
| **默认干净，需要时才展开** | 引用角标默认折叠。日常对话满屏标注会很吵 |
| **形象保留，界面专业** | 小虚拟形象负责个性与陪伴，主界面负责效率——不是二选一 |
| **后端不动** | 两个前端（桌宠 / 主界面）都只是界面，共用同一个后端 |

## 3. 三块工作

---

### ① 主界面重做（核心）

**布局**：左对话 + 右常驻记忆面板

```
┌──────────────────────────────────────┐
│ 状态栏：下次检查 14:58 · 记忆 147 条    │
├────────────────┬─────────────────────┤
│                │ 本次依据的记忆        │
│   对话区        │ · 学吉他（今天）     │
│   [回答+角标]  │ · 前端 UI（8月）     │
│                │ · [灰] 已过期        │
├────────────────┴─────────────────────┤
│ 输入框                                │
└──────────────────────────────────────┘
```

**记忆面板是本项目的差异化**，普通聊天机器人没有：
- 显示本次回答依据了哪几条记忆
- 点开看原文、来源（对话中学到 / 外部导入 / 待验证）、时间
- **当场改**或标"不重要"
- 被 supersede 的旧记忆标灰，说明为什么没采用

**引用角标呈现**：
- 正文关键词后跟小角标（¹²）
- 悬浮/点击 → 显示该条记忆
- 底部"本次依据 N 条记忆"，默认折叠

**技术**：
- 保留 React 19 + Vite + TypeScript
- 移除 Phaser（主界面不需要游戏引擎）
- 加 Tailwind（比手写 CSS 快，且好统一调性）

**验收**：
1. 能提问并收到回答
2. 回答带角标，点开能看到对应记忆原文
3. 记忆面板显示的条目与角标一致
4. 改一条记忆后，下次回答跟着变

### ② 桌宠（Mac 优先）

**形态**：透明、无边框、置顶、鼠标可穿透的小窗口，像素形象常驻桌面

**为什么先做 Mac**：你当前用 Mac。Electron 跨平台，Windows 后面打包即可（平台特定配置另说，见 §5）

**技术原理**：把窗口"伪装"成不像窗口
```js
new BrowserWindow({
  transparent: true,      // 背景透明，只显示角色
  frame: false,           // 去掉边框标题栏
  alwaysOnTop: true,      // 永远在最上层
  skipTaskbar: true,
})
win.setIgnoreMouseEvents(true)          // 鼠标穿透
win.setVisibleOnAllWorkspaces(true)     // 所有桌面可见
```

**三个必须处理的坑**（不做就不是桌宠）：

1. **穿透与可点的矛盾**
   设了穿透就点不到它。做法：鼠标移入角色区域时取消穿透，移开恢复。

2. **macOS 多桌面 / 全屏**
   切换 Space 或开全屏应用时，默认会盖住或消失，需要上面那行 `setVisibleOnAllWorkspaces`。

3. **必须有托盘图标**
   菜单栏放个小图标，右键可：显示/隐藏、打开主界面、退出。否则你没法退出它。

**形象状态**（不只是好看，承担状态指示）：

| 状态 | 表现 |
|---|---|
| 空闲 | 轻微呼吸 / 眨眼 |
| 思考中 | 转头 |
| 检索到记忆 | 亮一下 |
| **有要紧的事** | 明显跳动 + 角标 ← 最有用 |
| 点击 | 唤起主界面 |

**验收**：
1. 不打开浏览器，它也在桌面上
2. 鼠标能穿过它点到下面的窗口（不挡干活）
3. 鼠标移到它身上能点击，点开主界面
4. 切换桌面 / 开全屏应用，它还在
5. 菜单栏有图标能退出

**关于签名**：未签名应用首次打开会被 Gatekeeper 拦（右键→打开）。先用免费 Apple 账号自签名解决，**不买付费账号**（$99/年，自用没必要）。

### ③ 手机端（PWA）

**形态**：对话为主 + 底部上滑记忆抽屉

```
┌─────────────┐
│ 状态：2 条要紧│ ← 通知进来点这里
├─────────────┤
│  对话主区     │
│  [回答+角标] │
├─────────────┤
│ 依据 2 条 ▲  │ ← 上滑展开
│ [输入]       │
└─────────────┘
```

**注意**：PWA 的"安装应用"需要 HTTPS，服务器目前无域名无证书。
→ 但**加到主屏幕**在 http 下也能用（只是不能"安装"）。
→ 桌面应用（②）不走这条路，所以不受影响。

**验收**：
1. 手机浏览器能打开并对话
2. 上滑能看到记忆面板
3. 能加到主屏幕，图标正常

## 4. 执行顺序

```
阶段0  最小桌宠（半天）  ← 先验体验，不追求好看
       显示形象 + 悬浮不挡鼠标 + 点击唤起
       你感受一下"它一直在那儿"要不要得
              ↓ 认可再做下面的
阶段1  主界面骨架        React+Tailwind，对话能跑通
阶段2  记忆面板 + 引用角标  ← 差异化所在，重点
阶段3  桌宠完善          动画 + 状态联动
阶段4  手机端 PWA
阶段5  Windows 打包
```

**为什么桌宠排在前面**：它是主观体验，光讨论不出结果。先用最小版本让你摸到，认可了再投入。这跟你定的"先用上才知道"是一个道理。

## 5. 跨平台（Mac → Windows）

Electron 一套代码，但打包配置要分开：

| 事项 | Mac | Windows |
|---|---|---|
| 打包产物 | `.app` / `.dmg` | `.exe`（NSIS） |
| 签名 | 免费账号自签名够用 | 未签名会有 SmartScreen 警告 |
| 特有坑 | 多桌面、全屏盖住 | 任务栏、DPI 缩放 |
| 托盘 | 菜单栏 | 右下角系统托盘 |

阶段 5 我会另写 Windows 专项清单，现在不铺开。

- ❌ 多 Agent 协作（定位上已降级）
