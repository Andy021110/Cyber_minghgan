# 邮件重要性判定（mail/triage.py）实施计划

> 日期：2026-09-03 · 前置：邮件收发链路已打通（Gmail + 163 双向验证通过）

## 1. 目标

让邮件从"能收"变成"有用"。现在 40 封邮件平铺在面前，跟收件箱没区别；
判定层负责把它们分成三档，只对真正要紧的打断你。

## 2. 设计

### 三档输出

| 档 | 含义 | 行为 |
|---|---|---|
| `NOW` | 需要你近期处理 | 立即推送 |
| `DIGEST` | 值得知道，不急 | 攒进半天汇总 |
| `IGNORE` | 群发/营销/无需行动 | 不出现 |

### 三层判定

| 层 | 作用 | 本期状态 |
|---|---|---|
| **规则层** | 通用信号（付款异常、有时限、安全提醒、群发） | ✅ 本期实现 |
| **记忆层** | 个性化（涉及你在跟的项目/关心的人吗） | ⚠️ 只留接口，等 Phase 1 |
| **反馈层** | 校准（你标"不重要"→ 降权） | ✅ 本期实现（简单存储） |

**为什么记忆层本期只留接口**：它依赖记忆治理（BC-011 来源 / BC-012 去重 /
BC-005 supersede），而那些还没做。现在硬接等于在不可靠的数据上做判定，
会得出"涉及你在跟的项目"这种看似聪明实则随机的结论。留接口不阻塞本期见效。

### 核心原则：宁可漏，不要吵

**依据**：误报的直接后果是你会关掉通知，系统随即失效——这是唯一一个
"做错了就彻底没用"的失败模式。漏报顶多晚半天看到，可恢复。

具体体现：
- 默认档是 `DIGEST` 而不是 `NOW`（拿不准就进汇总，不打断）
- 只有**明确**的行动信号才升到 `NOW`
- 群发邮件除非含强信号，否则不进 `NOW`

## 3. 步骤

### Step 1 · 预登记实验
- 依据：实验关联率目前仅 30%，不能再先做后补
- 产出：`EXP-008`

### Step 2 · 规则层实现
- 依据：原型已用 40 封真实邮件验证过信号识别有效
  （实际捞出 2 封订阅过期邮件：`Your Subscription Will Expire`、
  `Your subscription to jasmine has expired`）
- 信号清单：群发 / 付款异常 / 有时限 / 安全提醒 / 含验证码 / 营销
- 产出：`mail/triage.py` 的 `classify()`

### Step 3 · 反馈层
- 依据：没有反馈循环，判定永远停在初始准确率
- 设计：按**发件人域名**记录权重（不是整封邮件），存 JSON
- 产出：`record_feedback()` + 持久化

### Step 4 · 测试
- **关键约束：测试不能依赖真实邮箱**（需凭证 + 隐私）
  所以用**脱敏的合成样本**——结构相同、内容虚构
- 依据：真实验证昨天已做过，回归测试要的是可复现，不是真实
- 产出：`tests/test_triage.py`

### Step 5 · 真实邮件验收
- 跑一次两个邮箱的真实邮件，输出三档分类结果
- 你人工核对：判为 `NOW` 的是不是真的重要
- 产出：验收报告（数字 + 你的主观评价）

## 4. 明确不做（本期）

| 不做 | 理由 |
|---|---|
| 记忆层实装 | 依赖未做的记忆治理，硬接是假智能 |
| 定时 check / 推送 | 判定稳定后再接，否则打扰控制不住 |
| LLM 判定 | 成本高、不可复现、无法进 CI；规则层够用先上规则 |
| HTML 内容深度分析 | 过度设计，先覆盖真实邮件里出现的主要信号 |

## 5. 风险

| 风险 | 应对 |
|---|---|
| 规则太保守，`NOW` 档长期为空 | Step 5 由你人工核对，空了就调；宁可空也别吵 |
| 合成样本覆盖不全 | 测试里明确标注样本来源，真实验证另做 |
| 反馈层被滥用（误标后回不来） | 权重只影响排序，不做硬过滤；可重置 |
