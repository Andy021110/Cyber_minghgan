# 产品形态与前端规划

> 日期：2026-08-30 · 状态：待用户确认
> 触发：用户反馈「能跑，但美工非常差」，并要求先统一梳理现状 / 问题 / 定位 / 形态

---

## 0. 结论先行

**美工差的根因不是"画得不好"，而是产品形态没定。**

现在一个界面里同时塞了三种交互范式：像素世界（探索沉浸）、管理面板（效率工具）、对话（聊天）。
它们的视觉语言天然不同，硬凑在一起的结果是每一套都做不完整。

所以顺序是：**先定形态 → 再定视觉 → 最后才是素材精修**。反过来做（先换皮）只会重蹈覆辙。

## 1. 现状盘点

### 1.1 已经建成的（可用资产，不要推倒重来）

| 层 | 内容 | 状态 |
|---|---|---|
| 像素世界 | Phaser 3：World / Study / Office / Gym 四场景 + Player / NPC / TriggerSystem | ✅ 可运行 |
| 面板层 | React 19：对话 / KG 图谱 / 审核 / 任务板 | ✅ 可运行 |
| 后端 | 8 个接口全部可用，SSE 流式对话 | ✅ 已验证 |
| 资产 | 地图 json ×3、NPC 精灵 ×5、地形图集 | ⚠️ 风格不统一（见 1.2） |

### 1.2 四个客观缺陷（依据：设计令牌与代码，非主观评价）

**缺陷 1：两套色系正面对冲**

`src/styles/tokens.css` 里同时存在两套：

```css
/* 面板层 — 羊皮纸暖棕 */
--panel-bg: #c8a060;  --panel-border: #6b3a10;
/* 游戏层 — GitHub Dark 冷灰 */
--game-bg:  #0d1117;  --game-card: #161b22;  --game-text: #c9d1d9;
```

暖棕面板 + 冷灰世界同屏显示。冷暖对冲是廉价感最直接来源。
（`#0d1117` 正是 GitHub Dark 的背景色，应该是早期调试时直接借用的。）

**缺陷 2：像素字体不支持中文**

`--font-pixel: 'Press Start 2P'` —— 该字体**只有拉丁字符**，无 CJK。
中文内容回退到 `Noto Sans Mono`，结果中英文用两种字体混排，视觉断裂。

**缺陷 3：字号过小**

HUD 正文 `font-size: 9px`，indicator `7px`。在 2x 屏上必然发虚、难辨认。

**缺陷 4：素材拼凑 + 版权风险**

星露谷原版角色精灵（alex / harvey / kent / Sebastian）与自制占位 tileset 混用，风格不统一。
且这些**第三方游戏素材已提交在公开仓库**（与 README 第 9 节自己的声明冲突）。

### 1.3 已知的功能性坑（上一轮发现，必须先修）

`frontend/src/api/client.ts` 的 `chatStream` 静默吞错：

```js
} catch { return; }
if (!res.ok || !res.body) return;
```

后端任何故障在界面上都表现为"什么都不发生"——**先修这个，否则后面所有视觉改动都在盲改**。

## 2. 定位（承接此前澄清）

**可信的个人代理——深度在记忆治理，不在工具数量。**

但前端要分清楚服务谁，因为两类用户的需求是冲突的：

| 用户 | 场景 | 要什么 |
|---|---|---|
| **你（自用）** | 查记忆、审批写入、维护 | **效率**。3 秒内拿到答案 |
| **访客/面试官（对外）** | 主页上提问 | **体验**。一进去就知道能问什么、答案可不可信 |

→ **结论：两套形态，不要一套通吃。** 用一套界面同时满足"高效维护"和"首次到访的引导"，结果两边都平庸。

---

## 3. 形态规划

### 3.1 桌面端（自用 + 演示）

**主形态：对话为中心，像素世界降为氛围层（默认折叠）**

```
┌──────────────────────────────────────────────┐
│ HUD：房间 / 待审数量 / 模式切换                │
├───────────────────────┬──────────────────────┤
│                       │  记忆面板             │
│   对话区（主）         │  · 本轮检索到的节点   │
│                       │  · 点击可溯源到原文   │
│   [输入框]            │  · 待审写入队列       │
├───────────────────────┴──────────────────────┤
│ ▸ 像素世界（默认折叠，点开进入 Phaser）         │
└──────────────────────────────────────────────┘
```

**理由**：像素世界好看但不高效。自用场景下它不能占主界面，否则每次查记忆都要先"走路"。
演示时展开，就是亮点；日常收起，就是效率工具。

### 3.2 移动端（对外主页为主）

**主形态：一屏问答 + 引导清单**

```
┌────────────────────┐
│ 身份卡              │
│ 明翰 · AI 代理      │
│ ⓘ 由本人资料驱动，   │
│   不代表本人实时表态 │
├────────────────────┤
│ 可以问我：           │
│ [项目经历] [技术选型] │
│ [学习路径] [偏好]    │
├────────────────────┤
│                    │
│  回答区             │
│  …带引用角标¹ 可展开 │
│                    │
├────────────────────┤
│ [输入…]             │
└────────────────────┘
```

**理由**：
- 访客在手机上不会去逛像素世界
- **引导清单是幻觉防线里最便宜的一道**——命中率上去，拒答率下来，暴露面最小
- 身份卡上的 ⓘ 声明是诚信底线（不能让 AI 冒充本人）

## 4. 视觉统一方案（解决"美工差"）

| 项 | 现在 | 改为 |
|---|---|---|
| 色系 | 暖棕 + GitHub Dark 冷灰并存 | **统一暖色羊皮纸**，弃用 `#0d1117` |
| 字体 | Press Start 2P（不支持中文） | 支持中文的像素字体（如 Zpix）或统一 Noto Sans SC + 像素描边 |
| 字号 | HUD 9px / 7px | 正文 ≥13px，辅助 ≥11px |
| 素材 | 星露谷原版 + 自制占位混用 | 统一为自制或 CC0 素材（同时解决版权） |

**这四项做完，视觉会从「差」直接跳到「能看」，而且成本只有 1 天左右。**

---

## 5. 分期计划

| 阶段 | 内容 | 成本 | 产出 |
|---|---|---|---|
| **P0** | 修 chatStream 静默吞错 + 色系统一 + 字体字号修正 | 1 天 | 从「差」变「能看」，且不再盲改 |
| **P1** | 桌面端改对话为中心，像素世界折叠 | 2–3 天 | 自用效率可用 |
| **P2** | 移动端对外主页（身份卡 + 引导清单 + 引用溯源） | 3–5 天 | 服务求职的展示面 |
| **P3** | 素材替换（合规 + 风格统一） | 视素材而定 | 合规 + 视觉完整 |

---

## 6. 需要你拍板的三个决策

1. **素材**：换成自制/CC0（工作量大但一劳永逸），还是**前端不公开、仅本地跑**（省事，但失去展示价值）？
2. **像素世界**：保留（演示亮点，但占开发量），还是砍掉（聚焦效率形态）？
3. **移动端优先级**：先做对外主页（直接服务求职），还是先打磨自用体验？

---

## 7. 与其他规划的关系

- 幻觉兜底（引用校验 / 只答检索到的 / 转真人）→ 落在 P2 移动端与 P1 对话区
- public/private 可见性硬隔离 → 是对外主页的上线前置条件
- 定量改进（打分量纲归一化）→ 不影响前端，可并行
