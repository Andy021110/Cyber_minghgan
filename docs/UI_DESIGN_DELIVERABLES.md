# 赛博明翰 · UI 设计交付规格

> 版本：2026-06-05  
> 受众：UI 设计师  
> 用途：明确每项设计交付物的内容、尺寸、格式与用途，确保设计产出可以直接交给前端实现

---

## 零、项目背景

赛博明翰是一个**像素风 RPG × 个人认知镜子**。用户操控一个玩家角色在像素风房子里行走，通过靠近 NPC 和物件触发 AI 对话，AI 持续维护一张关于「这个人是谁」的认知图谱（KG）。

**⚠️ 重要认知对齐：Id / Ego / Superego 是后端 KG 的数据分层标签，不是可见的游戏场景。**  
设计师不需要也不应该为这三层画对应的三个独立场景。它们只出现在数据面板（/kg 浏览界面）里，作为节点的分类标签显示。

### 像素风硬性约束

- 圆角：0px（或最多 2px，谨慎使用）
- 阴影：像素化 drop-shadow，偏移 2-4px，无模糊
- 图标：16×16 或 32×32 像素栅格，手绘像素风
- 动画参考帧率：8fps（帧跳跃感，不是贝塞尔曲线）

## 一、设计规范文档（Design Tokens / Style Guide）

### 1.1 色彩规范表

**交付内容**：完整的颜色 Token 表，包含：主色、辅色、语义色（成功 / 警告 / 错误 / 信息）、背景层级色、边框色、文本层级色。

**格式**：Figma 样式 / 导出为 JSON Token 文件（`tokens.json`）

**尺寸**：色块展示页，A4 或无限画布，色值标注 Hex + RGB

**用途**：前端直接转化为 CSS 变量；色板统一后所有组件不会出现色值不一致

---

### 1.2 字体规范

**交付内容**：

| 字体用途 | 字体名称 | 字重 | 字号范围 |
|----------|----------|------|----------|
| 标题 / 系统标识 | Press Start 2P | Regular（唯一） | 12px / 16px / 24px |
| 内容正文 | Noto Sans Mono / 系统等宽字体 | Regular + Bold | 12px / 14px |
| 辅助标签 | 同正文字体 | Regular | 10px / 11px |

**格式**：Figma 文字样式，导出文字规范截图 + 字体文件（`.ttf` 或 `.woff2`）

**注意**：`Press Start 2P` 不支持中文，中文内容一律使用等宽字体（如 `Noto Sans Mono`）

---

### 1.3 像素图标集

**交付内容**：项目所需全部功能图标，每个图标提供 2 尺寸版本

| 图标 | 用途 | 尺寸 |
|------|------|------|
| 知识图谱（节点连线） | 导航 / 入口 | 16×16 + 32×32 |
| 审批（打勾 / 叉叉） | /review 操作按钮 | 16×16 |
| 归档（文件夹） | 节点归档状态 | 16×16 + 32×32 |
| 合并（双箭头合一） | /prune merge | 16×16 |
| 老化（沙漏） | staleness 指示 | 16×16 |
| 设置（齿轮） | 设置入口 | 16×16 |
| 通知（信封/铃） | 通知数量徽章 | 16×16 |
| Id 层标识（火焰） | 层级标识 | 16×16 + 32×32 |
| Ego 层标识（秤） | 层级标识 | 16×16 + 32×32 |
| Superego 层标识（眼睛） | 层级标识 | 16×16 + 32×32 |

**格式**：PNG（透明背景）+ SVG 双版本；PNG 需提供 1x / 2x（@2x Retina）两份

**命名规范**：`icon-{name}-{size}.png`，如 `icon-archive-16.png`

## 二、核心界面设计稿

> 所有界面均以 HTML/CSS 面板叠加在 Phaser.js 游戏画布上方，游戏世界始终可见于背景。

### 2.1 游戏世界主画面

**用途**：用户打开应用后的第一个画面，也是 80% 时间停留的地方。Phaser.js 渲染，不属于 HTML/CSS 层。

**交付内容**：

- 线框图 × 1：标注房间分布、NPC 位置、任务板位置、各房间门洞
- 高保真插图参考 × 2 种状态：
  1. 无待处理任务（任务板无叹号）
  2. 有待处理任务（任务板显示叹号标识）

**尺寸**：1440×900（设计基准画布）

**关键区域标注**：

| 区域 | 内容 |
|------|------|
| 中央活动区 | 赛博明翰 NPC 站立位置、任务板挂墙位置 |
| 各房间入口 | 门洞处标注「走近触发提示」的视觉暗示（地面光晕或箭头） |
| 顶部 HUD | 当前房间名、通知角标（叠在游戏画面上的薄 HTML 条）|

---

### 2.2 对话框（NPC 交互）

**用途**：玩家靠近任意 NPC 按 E 后弹出，游戏背景保持可见。适用于赛博明翰主对话和所有专项 NPC 对话。

**交付内容**：高保真设计稿 × 3 种状态：

| 状态 | 说明 |
|------|------|
| 正常对话 | 玩家和 NPC 头像各在两侧，文字流式出现 |
| AI streaming | 打字机光标闪烁（`\|`，8fps），NPC 头像有说话动效 |
| 反刍主动开口 | NPC 头像有强调边框，气泡带「💡」标识，区分于普通回复 |

**布局**：底部横向对话框，占画面下方约 25%，左侧 NPC 全身像、右侧玩家全身像，中间文字区，右上角 X 关闭。全身像直接取对应角色 Sprite Sheet 的正面朝前帧，放大 2x 显示。

**尺寸**：1440×220px（对话框区域），角色全身像显示区域 64×96px

---

### 2.3 任务板覆盖面板（/review 入口）

**用途**：玩家走到任务板按 E 弹出，汇总所有需要人工处理的系统任务。参考星露谷「背包/物品栏」覆盖面板风格。

**交付内容**：高保真设计稿 × 2 种状态：

| 状态 | 说明 |
|------|------|
| 有任务 | 列表展示各类待处理条目，每条有来源标签 + 数量 |
| 空状态 | 「暂无待处理任务」空态插图 |

**条目类型**：

| 来源 | 显示文案示例 |
|------|------------|
| 蓄水池审批 | `[健身房] 3 条健康观察待审批` |
| 反刍新特征 | `[赛博明翰] 发现新行为模式，待确认` |
| 节点老化 | `[KG] 5 个节点接近归档阈值` |

**布局**：全屏覆盖，像素风边框，游戏画面在背后（半透明遮罩），右上角 X 随时关闭。内容区最大宽 640px 居中。

---

### 2.4 /review 审批面板

**用途**：从任务板点击「待审批」条目后展开，在客厅原地完成逐条审批，不跳转房间。

**交付内容**：高保真设计稿 × 4 种状态：

| 状态 | 说明 |
|------|------|
| LOG 路由条目 | 直接 Y/N，无相似节点步骤 |
| KG 路由 + 有相似节点 | 显示相似卡片列表，选择追加或新建 |
| KG 路由 + 无相似节点 | 直接进 importance 确认 + description 编辑 |
| 空状态 | 全部审批完毕的完成提示 |

**关键组件**：

| 组件 | 说明 |
|------|------|
| 条目卡片 | 观察内容 + 原始证据（折叠）+ AI 分类理由 |
| 相似节点卡片 | 节点标题 + 层级色标 + importance + 相似原因 |
| importance 滑块 | 1-10，像素风样式 |
| 操作按钮组 | 追加 / 新建 / 跳过 / 拒绝，标注键盘快捷键（Y / N / s / q） |

**尺寸**：全屏覆盖，内容区最大宽 760px 居中

---

### 2.5 /kg 知识图谱面板

**用途**：浏览全部认知节点，低频但重要。从任务板或物件触发，覆盖面板形式。

**交付内容**：高保真设计稿 × 2 种视图：

| 视图 | 说明 |
|------|------|
| 卡片列表视图（主视图） | 三列（Id / Ego / Superego），节点卡片展示 |
| 力导向图视图 | 节点圆形，层级配色，点击展开详情（参考现有 `docs/cyber_minghan_graph.html`） |

**关键组件**：

| 组件 | 说明 |
|------|------|
| 层级 Tab | 全部 / Id / Ego / Superego / 已归档，激活态用对应层颜色 |
| 节点卡片 | importance 色标 + 标题 + 描述预览（2 行截断） |
| 节点展开 | 抽屉或 Modal，展示完整 evidence + 操作按钮 |
| importance 颜色映射 | 1-3 灰、4-6 白、7-8 黄、9-10 红 |
| 归档节点 | 灰度处理，archive_reason 角标 |

---

### 2.6 /prune 老化管理面板

**用途**：节点老化评估 + 归档决策，低频操作，从任务板条目入口触发。

**交付内容**：高保真设计稿 × 1（含所有操作状态标注）

| 状态 | 内容 |
|------|------|
| 分布概览 | 候选归档 N 条 / 接近阈值 N 条 / 健康 N 条 统计卡片 |
| 单条裁决 | 节点卡片 + staleness 分数 + 归档 / 提升 importance / 跳过 按钮 |
| 完成状态 | 本次处理 N 条的总结提示 |

**尺寸**：全屏覆盖，内容区最大宽 680px 居中

---

### 2.7 房间入口确认提示

**用途**：玩家走到专项房间门口时触发，询问是否进入对应模式。属于 HTML/CSS 层，叠在游戏画面上方。

**交付内容**：高保真设计稿 × 1，含两种状态：

| 状态 | 说明 |
|------|------|
| 进入提示 | 显示房间名 + 模式说明 + Y / N 操作 |
| 取消（N）| 提示消失，玩家继续在游戏世界行走 |

**布局**：屏幕中央偏上，小型浮窗，不全屏。像素风边框，背景半透明，内容简洁。

示例文案：
```
┌─────────────────────────┐
│  健身房                  │
│  进入健康管家模式？        │
│                         │
│    [ Y 进入 ]  [ N 取消 ] │
└─────────────────────────┘
```

**尺寸**：浮窗约 320×120px，居中显示，按钮区键盘可操作（Y / N）

## 三、像素场景与角色

### 3.1 主世界地图（Tilemap）

**用途**：游戏世界的完整平面图，玩家角色在此行走导航。参考星露谷俯视室内风格（木地板、墙壁、门洞连通各房间）。

**空间结构**：
```
┌──────────────────────────────┐
│   健身房        学习室         │
│  （健康管家）   （学习助手）     │
│                              │
│       中央活动区               │
│   （赛博明翰 NPC + 任务板）     │
│                              │
│   办公室        [未来扩展]      │
│  （工作助手）                  │
└──────────────────────────────┘
```

**交付规格**：

| 交付物 | 尺寸 | 格式 | 说明 |
|--------|------|------|------|
| Tileset 图块集 | 16×16px / 块 | PNG | 地板、墙壁、门洞等基础图块 |
| 主世界完整地图 | 参考 Tiled 编辑器格式 | JSON + PNG | 供 Phaser 直接加载 |

**氛围**：温暖木质室内，暗色调（`#0d1117` 打底），各房间有轻微色温差异（功能区可略偏冷）

---

### 3.2 像素角色

**⚠️ 规格约束（所有角色共用，必须严格一致）**：

| 参数 | 规格 |
|------|------|
| 单帧尺寸 | 32×48px |
| 动作集 | 站立待机 4 帧、行走上/下/左/右各 4 帧、交互动作 2 帧，共 22 帧 |
| Sprite Sheet 排列 | 行 = 动作，列 = 帧，从左到右，顺序固定 |
| 格式 | PNG 透明背景，附帧坐标说明文档 |

> 规格一致的原因：游戏代码通过 key 名加载角色，切换角色方案只需换文件路径，不改代码。

**角色清单**：

| 角色 | 版本数 | 说明 |
|------|--------|------|
| Player 角色 | 1 版 | 用户操控的小人 |
| 赛博明翰 NPC | **3 版**（见下） | 住在中央区，是用户的认知镜子 |
| 健康管家 NPC | 1 版 | 住在健身房 |
| 工作助手 NPC | 1 版 | 住在办公室 |
| 学习助手 NPC | 1 版 | 住在学习室 |

**赛博明翰 NPC 三版设计方向**：

| 版本 | 设计方向 | 说明 |
|------|----------|------|
| v1 | 镜像版玩家 | 外形与 Player 角色接近，强化「认知镜子」隐喻 |
| v2 | 设计师自由发挥 A | 独立形象，有辨识度 |
| v3 | 设计师自由发挥 B | 另一套独立形象 |

三版帧规格完全相同，仅视觉设计不同。

> 对话框里的角色显示直接复用 Sprite Sheet 正面帧放大 2x，无需额外绘制肖像图。

### 3.3 可交互物件

每个房间 1-3 个可按 E 交互的物件，每个物件提供两种状态：普通 + 激活（发光/闪烁边框）。

| 物件 | 所在房间 | 触发功能 | 尺寸 |
|------|----------|----------|------|
| 任务板（公告栏） | 中央区 | 打开 review 面板 | 48×32px |
| 体重日历 | 健身房 | 展示健康趋势图表 | 32×32px |
| 训练记录本 | 健身房 | 展示训练日志 | 16×32px |
| 任务白板 | 办公室 | TBD | 48×48px |
| 书架 | 学习室 | TBD | 48×48px |

**格式**：独立 PNG 透明背景，1x + 2x 各一份，命名：`obj-{name}-normal.png` / `obj-{name}-active.png`

## 四、交互动效规格

### 4.1 房间切换动画

**描述**：玩家走进或走出房间时的过渡效果

**规格**：像素化淡入淡出，持续 300ms，分 4 帧（0% / 33% / 66% / 100% 透明度）

**交付**：Figma Prototype 演示 + 帧序列截图说明

---

### 4.2 节点写入图谱动效

**描述**：新节点写入 KG 时，/kg 面板对应层级的 Tab 高亮一秒，给玩家写入成功的即时反馈

**规格**：目标 Tab border-color 从对应层色渐变到基础边框色，持续 1s，分 6 帧

**交付**：Figma Prototype 演示

---

### 4.3 AI Streaming 打字效果

**描述**：AI 回复文字逐字出现

**规格**：光标样式（`|`）闪烁，每 125ms 切换一次（8fps）

**交付**：文字说明，无需设计稿（前端自行实现）

## 五、响应式与适配说明

当前以 **桌面端 1440px** 为基准设计，不要求完整响应式布局，但需要标注：

| 断点 | 处理方式 |

| ≥1280px | 功能面板三列卡片视图正常展示 |
| ≥768px（平板） | 功能面板内容区改为单列，操作按钮组改为底部固定栏 |
| <768px | 暂不要求（本地桌面应用，不需移动端适配）|

## 七、交付格式要求

| 项目 | 要求 |
