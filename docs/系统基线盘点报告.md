## 1. 数据契约盘点 (Data Schema Audit)

### 1.1 顶层骨架

```
yuanbao_cyber_minghan_kg.json
├── schema_version: "1.0"
├── created_at / updated_at: ISO 时间戳
├── processed_batches: list[str]  ← 8 个批次 ID
├── nodes:
│   └── Cyber_Minghan:
│       ├── Id_Dynamics:        list[node_obj]  (38 条)
│       ├── Superego_Dynamics:  list[node_obj]  (37 条)
│       └── Ego_Dynamics:       list[node_obj]  (38 条)
├── interactions: list[...]  (47 条)
└── metadata: { total_batches_defined, processed_batches, *_count }
```

顶层不是以 `Id/Ego/Superego` 为 Key 的扁平结构，而是统一挂在 `nodes.Cyber_Minghan` 下。

---

### 1.2 节点数据结构（典型样本）

所有三层的节点对象共享**同一个 Schema**，字段完全一致：

| 字段 | 类型 | 说明 |
|---|---|---|
| `layer` | `str` | `"Id"` / `"Superego"` / `"Ego"` |
| `event_label` | `str` | 事件语义标签（如"亲密渴望下的原始力比多驱力"） |
| `description` | `str` | 精神动力学分析文本（~80字） |
| `evidence` | `str` | 原始对话证据原文 |
| `batch_id` | `str` | 来源批次（如 `"Batch0"`） |
| `round_refs` | `list` | 轮次引用（当前全部为空 `[]`） |

> 节点是**扁平的结构体对象**，而非简单字符串列表。

---

### 1.3 主键检查

**结论：无 UUID，无任何唯一标识符字段。**

三层动力学节点均不含 `id`、`uuid`、`node_id` 等主键字段。当前唯一可用的定位键是 `(layer × batch_id × event_label)` 的组合——不稳定、不可直接寻址。

> ⚠️ **架构升级风险点**：Function Calling 的记忆引擎如需对单条节点进行读/写/更新操作，必须在重构前先为每条记录注入 UUID。

## 2. 代码基座盘点 (Code Architecture Audit)

### 2.1 依赖 SDK

```python
import anthropic  # anthropic-sdk (官方 Python SDK)
```

使用官方 `anthropic` 库，非 `openai` 兼容层，非裸 `requests`。

---

### 2.2 状态管理（多轮上下文）

```python
messages: list = []  # 在 run() 中初始化，会话全程复用

# 每轮追加：
messages.append({"role": "user",      "content": user_input})
messages.append({"role": "assistant", "content": assistant_response})
```

- 标准的**原地追加列表**模式，无截断、无压缩、无 token 上限保护。
- API 出错时会 `messages.pop()` 回滚最后一条 user 消息。

---

### 2.3 数据挂载方式

```python
system_prompt = load_cyber_brain()  # 启动时一次性调用

# load_cyber_brain() 内部：
# - 读取整个 JSON
# - 从三层各取前 5 条 → 格式化为文本摘要
# - 从 interactions 取前 6 条
# - 全部拼接成一个 f-string → 返回 system_prompt 字符串
```

**挂载模式：System Prompt 一次性字符串拼接（启动时静态注入）。**  
KG 数据在会话开始后**不会动态更新**，且只注入了各层前 5 条（共 113 条数据仅用约 15%）。

---

### 2.4 循环机制

```python
while True:
    user_input = input("你: ").strip()   # 阻塞式 REPL

    messages.append(...)                  # 追加 user
    client.messages.stream(...)           # 流式调用
    messages.append(...)                  # 追加 assistant

    # 无退出/截断/记忆持久化逻辑
```

标准的 `while True` + `input()` REPL，流式输出（`stream.text_stream`），**无持久化**（进程退出则 `messages` 丢失）。

## 3. 架构升级关键 Delta（供首席架构师参考）

| 维度 | 当前状态 | 升级所需补齐 |
|---|---|---|
| 节点寻址 | 无主键，仅靠 label 定位 | 为所有 113 条节点注入 UUID |
| KG 挂载 | 启动时静态注入前 5 条摘要 | 改为动态检索 → Function Call 按需拉取 |
| 记忆持久化 | 进程内临时 list，退出即销毁 | 会话 messages 序列化落盘 |
| 上下文管理 | 无截断，纯追加 | 5 轮反刍机制 → 滚动压缩或摘要 |
| SDK 兼容性 | `anthropic` 官方库 | Tool Use / Function Calling 原生支持，**无需换库** |
