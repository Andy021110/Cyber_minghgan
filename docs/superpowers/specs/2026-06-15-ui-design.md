# 赛博明翰 · UI 设计规格

> 版本：2026-06-15  
> 来源：UI brainstorm 对齐会话  
> 状态：已确认，待实现

---

## 一、技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| 游戏世界层 | Phaser 3 | 像素场景、角色行走、NPC 交互、触发系统 |
| 功能面板层 | React + Vite + TypeScript | 对话框、审批、KG、Prune 等所有 HTML 面板 |
| 两层通信 | CustomEvent（EventBus） | 事件命名合同保持不变，Phaser/React 实现代码重写 |
| 后端 | FastAPI（Python） | 完全不动，接口契约见 TECH_SPEC 第五章 |

**决策依据**：前端全新写（无现有代码需保留，也无美术资产），React 提供更好的面板开发体验和状态管理，Phaser 保留游戏层所需的 Tilemap / 动画 / 输入系统。TypeScript 全程。

## 二、视觉风格

### 2.1 整体方向

**星露谷式暖像素**——室内俯视场景，木质地板，有生活感，彩色家具。整体明亮温暖，不是暗色终端风。

参考基准：《星露谷物语》室内场景截图（暖木色调、俯视 45°、像素颗粒感）。

### 2.2 面板质感

所有 HTML 功能面板（对话框、审批、KG、Prune）延续游戏世界的暖色，不切换为暗色数据风。

**羊皮纸 / 卷轴风**：
- 面板底色：米黄色（约 `#c8a060`）
- 边框：深棕色（约 `#6b3a10`），2–4px 实线
- 正文：深棕色（约 `#2c1608`），可读性优先
- 面板阴影：像素化 `4px 4px 0 #1a0800`，无模糊
- 标题栏：深棕底色（约 `#8b6020`），金色文字（约 `#f0d090`）
- 卡片底色：中棕色（约 `#b89050`），边框 `#8b6020`

### 2.3 保留的语义色

Id / Ego / Superego 三层语义色在面板内保留，用于节点标识和 Tab 激活态：

| 语义 | 色值 | 用途 |
|------|------|------|
| Id 层 | `#e05c5c`（红） | 节点左侧色条、Tab 激活背景 |
| Ego 层 | `#3fb950`（绿） | 同上 |
| Superego 层 | `#f0a500`（橙） | 同上 |
| 成功/写入 | `#3fb950` | 审批「写入图谱」按钮 |
| 拒绝/危险 | `#e05c5c` | 审批「拒绝」按钮、老化紧急标识 |

### 2.4 像素风硬性约束

- 圆角：0px（所有面板和按钮）
- 阴影：像素化 `drop-shadow`，偏移 2–4px，模糊 0px
- 动画：帧动画 8fps，不使用贝塞尔曲线
- 字体：`Press Start 2P`（英文标题）+ `Noto Sans Mono`（中文正文）
- 图标：16×16 或 32×32 像素 PNG，手绘像素风

## 三、公私权限模型

| 维度 | 私有（owner） | 公开（访客） |
|------|---------------|-------------|
| 识别方式 | session token / user-id | 无 token，URL 直接访问 |
| 游戏世界 | 完全可见，可自由行走 | 完全可见，可自由行走 |
| NPC 对话 | ✅ 可触发，写入后端 | ✅ 可触发，只读 KG 做上下文 |
| 任务板 / 物件 | ✅ 按 E 触发审批等面板 | ❌ 按 E 无反应 |
| 审批 / KG / Prune 面板 | ✅ 可访问 | ❌ 完全隐藏 |
| HUD 任务板角标 | ✅ 显示待处理数量 | ❌ 隐藏 |
| HUD 设置入口 | ✅ 显示 | ❌ 隐藏 |
| HUD 空间标识 | 无（默认是自己的空间） | 显示「[owner名]的空间」 |

## 四、访客欢迎页

访客通过分享链接进入，到达欢迎页后再进入游戏世界。

**布局：名片式（B2）**

```
┌──────────────────────────────────┐
│  [头像/像素插图]  明翰             │
│                 一句话介绍         │
├──────────────────────────────────┤
│  这里有什么                        │
│  🏠 大厅    · 和赛博明翰聊天       │
│  🏋️ 健身房  · 健康与身体           │
│  💼 办公室  · 工作模式              │
│  📚 学习室  · 学习成长              │
├──────────────────────────────────┤
│         [ ▶ 进入空间 ]             │
└──────────────────────────────────┘
```

- 羊皮纸底色，深棕边框，整体延续游戏内面板风格
- 房间列表说明访客能做什么（每个房间可以和对应 NPC 聊天）
- 「进入空间」按钮触发 Phaser 场景加载，淡入动画

## 五、各功能面板设计

### 5.1 对话框

**默认态（底部横栏）**：
- 固定在屏幕底部，高约 25% 视口
- 左侧：NPC 全身像（Sprite Sheet 正面帧放大 2x，64×96px 显示区域）+ NPC 名称
- 中间：当前最新一条消息，streaming 时显示像素光标 `▌`（8fps 闪烁）
- 右上角：`↑ 历史` 按钮
- 底部：文字输入框 + 发送按钮
- 游戏世界在背景可见

**展开态（点击「↑ 历史」）**：
- 历史区从底部向上展开，占约 60% 视口
- 历史消息可滚动，最新消息固定在底部
- 消息气泡：NPC 消息左对齐（棕色底），用户消息右对齐（深棕底）
- 每条消息显示时间戳
- 当前消息 + 输入框始终固定在最下方
- 右上角变为 `↓ 收起` 按钮

**反刍提示**：NPC 主动开口时（reflection 触发），消息左上角显示 `💡` 角标，边框用金色高亮。

### 5.2 任务板（汇总入口）

走到任务板物件按 E 触发，全屏覆盖，内容区最大宽 360px 居中。

**三类条目**：

| 类型 | 角标颜色 | 说明 |
|------|----------|------|
| 蓄水池待审批 | 红色（`#e05c5c`） | 待人工决策的 AI 观察 |
| 反刍新模式 | 橙色（`#f0a500`） | 反刍引擎发现的新特征，待确认 |
| 节点老化提醒 | 灰色（`#8b8b8b`） | 进入老化阈值的节点 |

点击任意条目进入对应的详细处理面板。全部处理完后面板主体显示空状态提示。

### 5.3 审批面板

从任务板点入，逐条处理。

**面板内容（从上到下）**：
1. 返回按钮 + 进度「3/8」+ 来源标签（如「健身房」）
2. AI 观察内容卡片（深棕底，正文清晰）
3. AI 建议路由（写入图谱 / 只记日志）+ 建议层级 + 建议 importance
4. **你的判断**：可选文字输入框，写自己的看法或纠正（任何操作都保存）
5. **写入图谱的描述**：默认显示（因 AI 建议为「写入图谱」），用户选 N / S / Q 时折叠隐藏，选 Y 时重新展开，可直接编辑 AI 起草的节点描述
6. importance 滑块（1–10，像素风样式，可从 AI 建议值调整）
7. 操作按钮组：

| 按键 | 操作 |
|------|------|
| Y | 写入图谱（提交描述 + importance + 备注） |
| N | 拒绝（仅保存备注） |
| S | 只记决策日志（不写 KG） |
| Q | 跳过（下次再说） |

### 5.4 KG 浏览面板

从任务板或 HUD 入口触发，低频使用。

**顶部 Tab**：全部 / Id / Ego / Superego / 归档，Tab 右侧有 `?` 按钮解释三层含义。

**节点卡片**：
- 左侧 4px 色条标识层级（红/绿/橙/灰）
- 显示：层级标签 + 节点标题 + 描述预览（2 行截断）+ importance 数值
- 归档节点灰化（opacity 0.6）
- 点击展开完整内容（抽屉或 Modal）

**importance `?` 提示**：悬停 / 点击说明 1–10 的含义和颜色映射。

### 5.5 Prune 老化管理面板

从任务板条目入口触发。

**顶部统计卡片（三格）**：
- 紧急（红底）：staleness 超过阈值
- 接近（橙底）：接近阈值
- 健康（绿底）：正常

**逐条处理**：
- 节点标题 + staleness 分数（带 `?` 解释算法）+ 上次访问天数 + 当前 importance
- 操作按钮：归档 / 提升重要度 / 跳过
- 「提升重要度」点击后弹出数值输入（同时重置 last_accessed_at）

### 5.6 HUD 顶部栏

始终叠在游戏画面上方，高约 28px。

**私有模式**：
```
[🏠 当前房间名]  ────────  [📋 任务板 ⁴]  [⚙]
```
- 任务板按钮：有待处理条目时显示红色数字角标
- ⚙ 设置按钮（Phase 2 具体功能待定）

**公开模式（访客）**：
```
[👤 明翰的空间]  [🏠 当前房间名]  ────  [💬 和明翰聊天]
```
- 左上角空间标识让访客知道自己在别人的认知空间里
- 任务板 / 设置入口完全隐藏
- 保留「💬 聊天」快捷入口（点击等同于走到 NPC 按 E）

## 六、全局 `?` 帮助系统

所有需要解释的术语旁放置像素风 `?` 按钮（14×14px，深棕底，金色文字），点击弹出深色（`#2c1608`）小卡片说明。

**需要添加 `?` 的位置**：

| 位置 | 说明内容 |
|------|---------|
| KG Tab 旁 | Id / Ego / Superego 三层含义 |
| importance 旁 | 1–10 的含义，高值表示什么 |
| staleness 分数旁 | `days_since_last_access / importance` 的计算逻辑 |
| 审批面板路由选项旁 | 「写入图谱」vs「只记日志」的区别 |

## 七、Phase 2 预留

以下内容本版本不实现，在设计时预留扩展空间：

- **访客可交互装饰物件**：小球、小鸭子、会动的叶子等，增强游戏性，不涉及任何数据功能
- **更多专项房间**：办公室（工作助手）、学习室（学习助手），架构已在 TECH_SPEC roomConfig 预留
- **社交地图**：Phase 3，WorldScene 右下角门洞预留，不实现

## 八、不在范围内

| 不做 | 原因 |
|------|------|
| 移动端适配 | MVP 桌面端 1440px |
| 多用户 KG | MVP 单 owner，访客只读 |
| Unity / 非 Web 技术栈 | 公开分享需要 URL，Web 唯一合理选择 |
| 暗色数据终端风格面板 | 已决定延续暖色，不切换质感 |
| 访客写入 / 审批操作 | 访客仅对话，不接触任何写权限 |
