# 赛博明翰产品定位设计

> 日期：2026-06-15
> 状态：已对齐，待实现

---

## 定位

**一个以明翰为原型的认知系统，私有模式是你的思维镜子，公开模式是别人认识你的窗口。**

不是通用 AI 助手，不是数字分身展览品。核心价值在于：系统知道明翰是一个什么样的人，随着时间持续积累，越来越准。

---

## 两种访问模式

| 模式 | 用户 | 能做什么 | 看到什么 |
|------|------|----------|----------|
| 私有模式 | 只有明翰 | 对话 + 全部管理面板（/review、/kg、/prune） | 完整 KG + persona.md |
| 公开模式 | 任何访客 | 只能和赛博明翰 NPC 对话 | public 节点 + persona.md |

**同一套游戏界面，权限不同。** 公开模式下管理面板全部隐藏。

## 数据架构：MD + KG 双层驱动

### 两个文件，两种角色

| 文件 | 角色 | 更新频率 | 谁写 |
|------|------|----------|------|
| `yuanbao_cyber_minghan_kg.json` | 行为真相层——从真实对话中提炼的行为模式，证据驱动 | 日常持续更新 | 系统自动 + 你审批 |
| `persona.md` | 意识描述层——你有意识写下的自我描述，价值观、风格、典型反应 | 每 3-6 个月校准 | 你写，对齐校准时修改 |

### 公开版 System Prompt 构建方式

```
public system prompt =
    persona.md 全文
  + KG 中 visibility=public 的节点（按 importance 降序，取前 N 条）
```

私有版 system prompt 在此基础上额外注入所有 private 节点。

## KG 节点可见性字段

在现有节点 JSON 结构上新增一个字段：

```json
"visibility": "private"   // 默认值，只有私有模式可见
"visibility": "public"    // 进入公开版 system prompt
```

**触发时机**：`/review` 审批流程采纳新节点时，增加一步 visibility 选择。默认 `private`，用户主动标记才变 `public`。

Id 层的冲动节点通常保持 private；Ego 层的策略节点可以考虑 public——但最终由用户自己决定。

## 定期对齐机制

**目的**：KG 记录你实际上是谁，persona.md 记录你以为自己是谁。随着 KG 更新，两者会逐渐漂移，需要定期把 MD 更新到追上 KG。

**方向永远是 KG → MD**，KG 是真相来源，MD 追赶 KG，不反过来。

**触发频率**：每 3-6 个月一次（可配置）。

**流程**：

```
收集自上次对齐以来新增的 public 节点
    │
    ├─ 数量 ≤ 10 条
    │     直接并排展示 persona.md 和新节点
    │     用户自己判断是否需要修改 MD
    │
    └─ 数量 > 10 条
          AI 读取 persona.md + 所有新 public 节点
          归纳出 3-5 个关键矛盾点或漂移点
          用户逐条裁决：MD 要不要改、怎么改
          确认后更新 persona.md，提交 git
```
