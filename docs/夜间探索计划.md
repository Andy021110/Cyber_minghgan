## 2. 关键决策与论证依据

### D1. 先修静默吞错，而不是先改视觉

- **依据**：`frontend/src/api/client.ts` 中 `catch { return; }` 与 `if (!res.ok || !res.body) return;` 会吞掉一切后端错误
- **推理**：不修这个，后续任何视觉/交互改动都无法判断"是没生效还是后端挂了"
- **取舍**：多花 20 分钟，换后续所有改动可验证

### D2. 对外模式必须先做可见性硬隔离

- **依据**：实测 `CyberBrainStore.retrieve` **不过滤 visibility**（仅 `build_public_system_prompt` 过滤）；L0 原文层**根本没有 visibility 字段**
- **推理**：只要把 `retrieve_memory` 暴露给外部，private 节点（含真实人名、情感经历）会被直接检索出来
- **结论**：这是上线前置条件，不是优化项

### D3. 引用校验优于"让 LLM 自评有没有编造"

- **依据**：LLM 自评本身会产生幻觉；而"回答必须带 `[uuid:xxxx]`、且 id 必须在本次检索结果内"是**代码可验证**的
- **推理**：可验证的约束 > 不可验证的提示词
- **已写进代码注释**：`interrupt` 三约束（官方 Interrupts 文档：节点恢复时从头重跑）

### D4. 拒答策略按「后果主导、语档次之」

- **依据**：用户 2026-08-30 决策（能力/经历→体验优先，私密→信任优先）
- **推理**：开放档语料充分、代价低，体验优先几乎不增加风险；后果高的话题语料再足也不答
- **关键推论**：两策略不是妥协关系，各自适配自己的象限

### D5. 不自建全图，先接 interactions

- **依据**：全库节点间边数 = 0；规模仅 16.2k tokens（远未到需要图检索的量级）
- **反方证据**：Zep/Graphiti 在 LongMemEval 上 63.8% vs Mem0 49.0%，增益集中在时序(+38%)与多跳(+31%)
- **推理**：图的价值 = f(规模, 查询类型)，我们现在在"小规模"象限 → **方向对，但现在全量上图是过度设计**
- **折中**：先接 interactions（自带 trigger→resolution，几乎零成本），等分题型召回率数据再决定

### D6. 参数一律标注"待标定"，不自称有依据

- **现状**：`vector_alpha=0.4`、`half_life=180`、`keep_last=6`、`compact_threshold=12`、`min_effective=1.5` 全为拍定值
- **处置**：文档中标注待标定 + 给出标定方法（网格搜索 / 存活分析拟合）

## 3. 可回溯机制（本次严格执行）

| 机制 | 做法 |
|---|---|
| **一个变动一个 commit** | message 格式：`类型(范围): 摘要` + 正文写「决策依据 / 影响 / 回滚方式」 |
| **阶段 tag** | 每个优先级项完成后打 tag，如 `p0-frontend-fix`、`p1-public-mode` |
| **变更记录** | `docs/变更记录.md`：日期 / 改了什么 / 为什么 / 依据 / 如何回滚 |
| **决策记录** | 新增长期决策写入 `docs/关键决策记录.md`（背景/选项/决定/依据/后果） |
| **参数可追溯** | 拍定的参数在代码注释与文档中标注 `# 待标定` + 标定方法 |
| **测试守门** | 每个行为改动配测试，84 个基线测试不得回退 |
