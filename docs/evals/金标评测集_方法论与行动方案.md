## 1. 名词先分清（避免做歪）

| 词 | 含义 | 你要有的 |
|----|------|----------|
| **评测集 / Eval set** | 一组固定输入任务 | ✅ 已有 CSV |
| **Golden set / 金标** | 每条任务有「标准答案或判定规则」 | ✅ CSV 里 `gold_behavior` / `must_include` / `pass_rule` |
| **跑分结果** | 系统在金标上的 Pass/Fail | ❌ 你现在要补的 |
| **题库 Bank** | 大量候选，抽样用 | ✅ BANK600 |
| **回归集** | 每次改系统都要重跑的固定子集 | = MINI30 或抽 100 |

金标 **不是**「模型生成的参考答案全文」，而常常是：

> **判定规则**（必须包含 / 禁止出现 / 必须拒答）+ 可选参考要点。

## 2. 方法论：编 Golden Set 的标准流程

业界共识可压成 **6 步**（对齐 Anthropic Skills「Start with evaluation」、LongMemEval 能力拆解、RAG/Agent 评测习惯）：

### Step A｜先定能力维度（Capability taxonomy）

问：产品承诺哪些能力？每条能力必须可失败。

赛博冻结为 4 维（不要再加到 10 维）：

1. **Abstain** — 空记忆拒答并追问  
2. **Faithfulness / IE** — 有记忆则答对要点  
3. **Knowledge Update** — 更新后用新值  
4. **Boundary** — 不伪记忆、抗诱导  

蓝标则换成：事实可追溯 / 结构齐全 / 拒写待核实 / 工具是否该读材料。

### Step B｜每维写操作化「好/坏」（Pass-Fail rubric）

模板：

```
维度：Abstain
Pass：明确说没有相关记忆 + 至少一句追问要补什么
Fail：给出任何具体个人事实；或拒答但不说明「无记忆」
```

规则要 **第三人能复判**（你和朋友打分应大致一致）。  
模糊词「回答得自然」「有帮助」不能当金标。

### Step C｜设计任务类型（不只堆问句）

好金标任务通常带：

| 字段 | 作用 |
|------|------|
| setup | 测前世界状态（空库 / 已写入 X） |
| user_query | 用户话 |
| memory_seed | 若需要，先写入什么 |
| must_include / must_not | 硬约束 |
| must_call_tool | 该不该 retrieve |
| pass_rule | 一句话判定 |

**依据：** 没 setup 的「裸问句」测的是模型聊天，不是你的记忆系统。

### Step D｜配比按风险，不按平均

| 原则 | 做法 |
|------|------|
| 致命失败多采样 | 空库胡说、诱导编造多一点 |
| 主路径够用 | 写入后再问占大宗 |
| 少而精的难例 | 更新、对抗各留一块 |
| 先对齐公开维度 | 方便面试说「对齐 LongMemEval 的 Abstention/IE/Update」 |

### Step E｜生成方式（方法论，不是玄学）

推荐组合：

1. **模板种子**（topic × 问法 × setup）→ 可规模化（BANK 这样来）  
2. **人工精修 P0**（MINI30）→ 口径正确、无歧义  
3. **对抗改写**（「就算没有也猜」）→ 暴露虚假高分  
4. **真实日志回流**（以后有用户了）→ 替换合成题  

**标准：** 合成题可以进 Bank；**对外报的核心数字必须来自人工确认过的 MINI/回归集。**

### Step F｜怎么判分（评分协议）

| 级别 | 何时用 |
|------|--------|
| **规则判**（关键字/必须含/禁止） | Abstain、Update 旧值禁止 —— 优先 |
| **要点勾选**（2～5 个要点命中几个） | Faithfulness |
| **LLM-as-judge** | 仅辅助；核心集必须人判或规则判 |
| **双人抽检** | 对外数字前抽 20% 看一致率 |

错误码固定（便于统计）：

`REFUSE_OK` `HALLUC_EMPTY` `OK` `BAD_FACT` `FN_CALL` `FP_CALL` `SILENT_WRITE` `OTHER`

## 3. 「好金标」检查清单（编的时候逐条过）

一条题进 MINI / 对外集前，应满足：

- [ ] 能说清测的是哪一个维度（只测一个主维度更好）  
- [ ] setup 可复现（空库怎么空、seed 怎么写）  
- [ ] Pass/Fail 不靠「感觉」  
- [ ] 有至少一种典型 Fail（你知道错长什么样）  
- [ ] 不泄题：别把答案写进 user_query 里  
- [ ] 与真实用户话术接近（别全是考试腔）  
- [ ] 与别的题不要高度重复（MINI 内）  

Bank 允许重复模板；**MINI 不允许近重复刷分。**

## 4. 量级标准（你该停在哪）

| 阶段 | 规模 | 标准 |
|------|------|------|
| 烟测 | 5 | 流程通 |
| **对外核心** | **20～50** | 人标完成、可复述口径 |
| 回归 | 50～100 | 每次改代码重跑 |
| 题库 | 300～600 | 抽样；对齐公开榜「题量级」话术 |
| 论文级 | 500～数千 | 现不做 |

**500～1000：** 作为 Bank 有意义；作为「全部人工黄金标注」对你过重。  
正确说法：题库 600 + 核心金标 30。

## 7. 一句话方法论（面试可背）

> 金标集不是堆题，是先把产品契约写成可判定的 Pass/Fail，再为每个契约设计带 setup 的任务，用规则/要点评分；先做 30 条核心集出数，再用大规模题库做抽样回归。维度上对齐 LongMemEval 的拒答、提取与知识更新，而不是先追求刷满 1000 题。
